## Directory Purposes

**src/:**
- Purpose: Core application modules implementing RAG pipeline
- Contains: Python modules for document ingestion, semantic search, and chat interface
- Key files: `ingest.py`, `search.py`, `chat.py`

**.planning/codebase/:**
- Purpose: GSD-generated architecture and codebase analysis documents
- Contains: ARCHITECTURE.md, STRUCTURE.md, and future analysis documents
- Generated by: GSD map-codebase command
- Committed: Yes

## Key File Locations

**Entry Points:**
- `src/ingest.py`: PDF ingestion pipeline (run with `python src/ingest.py`)
- `src/chat.py`: Chat interface main entry point (run with `python src/chat.py`)

**Configuration:**
- `.env.example`: Template showing all required environment variables
- `docker-compose.yml`: PostgreSQL and pgvector service configuration
- `requirements.txt`: All Python package dependencies

**Core Logic:**
- `src/ingest.py`: PDF loading, chunking, embedding generation, vector storage
- `src/search.py`: Retrieval chain definition, prompt template, LLM context formatting
- `src/chat.py`: Search chain initialization, conversation loop, user interaction

**Supporting Files:**
- `document.pdf`: Sample PDF file for testing ingestion (path configured via `PDF_PATH` env var)
- `README.md`: Project description and execution instructions

## Naming Conventions

**Files:**
- Snake case: `ingest.py`, `search.py`, `chat.py`
- Pattern: Functional names matching pipeline stage

**Directories:**
- Lowercase: `src/`, `.planning/`
- Convention: One-word descriptive names

**Functions:**
- Snake case: `ingest_pdf()`, `search_prompt()`, `main()`
- Verb-noun pattern reflecting action

**Variables:**
- Snake case: `PDF_PATH`, `DATABASE_URL`, `PG_VECTOR_COLLECTION_NAME`
- Uppercase for environment variables and constants
- Template strings: `PROMPT_TEMPLATE`

## Where to Add New Code

**New Feature (e.g., document filtering, query rewriting):**
- Primary code: `src/search.py` (if search-related) or new `src/feature.py` module
- Tests: Create `tests/test_feature.py` if test directory established

**New Component/Module (e.g., document processor, embedding transformer):**
- Implementation: Create `src/processors/` subdirectory with new modules
- Pattern: Follow existing module structure with function-based exports

**Utilities (e.g., PDF parsing helpers, prompt formatting):**
- Shared helpers: `src/utils.py` or `src/helpers/` for multiple utilities
- Import pattern: `from src.utils import helper_function`

**New Embedding or LLM Provider:**
- Configuration: Add to `.env.example` and environment-based selection
- Implementation: Extend search.py with conditional provider logic or create `src/providers/` module

**Docker Volumes:**
- Purpose: PostgreSQL data persistence
- Mount point: `postgres_data:/var/lib/postgresql/data` (managed by Docker)
- Generated: Yes (at runtime)
- Committed: No (excluded from Git)

## Import Patterns

**Module imports from search in chat:**
```python
from search import search_prompt
```

**Environment variable loading:**
```python
from dotenv import load_dotenv
import os
load_dotenv()
PDF_PATH = os.getenv("PDF_PATH")
```

**LangChain integrations:**
- Document loaders: `langchain` or `langchain-community`
- Text splitters: `langchain-text-splitters`
- Embeddings: `langchain-google-genai` or `langchain-openai`
- LLMs: `langchain-google-genai` or `langchain-openai`
- Vector store: `langchain-postgres` with `pgvector`
